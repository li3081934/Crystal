# Mir2 装备词条系统（前缀 / 后缀）设计方案

> 状态：设计稿（待评审）
> 目标版本：`Envir.Version` 118 → 119
> 设计约束：与现有 6 套装备改造系统完全解耦；词条采用暗黑2 式前缀/后缀词形，但**不拼接到装备名**，只在详情与染色体现；词条强度按**怪物等级（ilvl）**分层；本期不做洗练玩法，但数据与接口必须为后续玩法预留。

---

## 0. 结论摘要

| 项目 | 结论 |
|---|---|
| 可行性 | 可行。新增一条独立数据线（`UserItem.Affixes` + 独立词条表），不触碰 `AddedStats` / `Awake` / `Slots` |
| 数据格式 | `UserItem` 增加 2 个字段，DB 版本 +1，**物品网络格式无版本协商 → 全端必须同版本发布** |
| 生成时机 | 仅怪物掉落点掷骰，`ilvl = 怪物等级`；商店/合成/任务奖励不带词条 |
| 属性生效 | 服务端 `HumanObject.RefreshStats` + 客户端 `UserObject.RefreshStats` 各加一处汇总 |
| 展示 | 客户端物品提示新增一节（按 Tier 逐行着色）；装备名**不拼词条**，仅按最高词条 Tier 染色；需要新增 1 个下发词条名表的包 |
| 本期工作量 | MVP 约 2 人日；含词形/染色/编辑器约 4–5 人日 |
| 后续扩展 | 洗练、重铸、词条转移、词条共鸣、条件词条均已在数据模型与 `AffixService` 中预留 |

## 1. 需求与边界

### 1.1 本期范围

1. 装备掉落时按怪物等级生成 1–4 条词条（前缀/后缀）。
2. 词条数值独立于现有「附加属性（`AddedStats`）」，互不污染。
3. 装备名保持基础名不变；词条以「详情区逐行显示 + 名字染色」体现，不拼接。
4. 词条数值真实参与战斗/面板计算（服务端权威，客户端一致）。
5. 工具提示独立一节展示词条，按 Tier 着色；装备名字按最高词条 Tier 染色。
6. 提供 GM 命令用于测试。

### 1.2 非目标（本期不做，但要能加）

- 洗练/重铸/词条转移 NPC 与货币。
- 词条图鉴、词条共鸣（套装效果）。
- 条件词条（"生命低于 30% 时……"）、百分比词条。
- 词条数值的线上热更新（重启生效即可）。

### 1.3 与现有 6 套改造系统的关系

现有系统全部围绕 `UserItem.AddedStats` 这一本账（详见 `docs` 之外的调研结论）：

| 系统 | 数据落点 | 入口 |
|---|---|---|
| 随机附加属性 | `AddedStats` | `Envir.UpgradeItem`（`Envir.cs:4547`） |
| 精炼 | `AddedStats[MaxDC/MC/SC]` | `PlayerObject.cs:12915` |
| 宝石合成 | 烘焙进 `AddedStats` + `GemCount` | `PlayerObject.cs:6676` |
| 插槽镶嵌 | `UserItem.Slots[]` | `PlayerObject.cs:4881` |
| 觉醒 | `UserItem.Awake` | `PlayerObject.cs:9060` |
| 重置附加属性 | 清 `AddedStats` / `GemCount` | `PlayerObject.cs:9244` |

**词条系统不进入上表任何一格**：用自己的字段、自己的生成入口、自己的汇总函数。因此：

- 精炼的「已有词条折算」看不到词条（`item.AddedStats.Count` 不变）。
- `ResetAddedItem` 只清附加属性，词条保留（需在白名单里显式带上）。
- 分解 `Quality()`、修理价、商店回收价默认不受词条影响（可配置开启）。
- 词条可以与随机附加属性**同时存在于同一件装备**，互不干扰。

## 2. 现状约束（设计依据）

### 2.1 物品存档格式

`UserItem.Save(BinaryWriter)`（[ItemData.cs:460-509](../Shared/Data/ItemData.cs#L460-L509)）**没有 version 参数**，永远写最新格式；读取端 `UserItem(BinaryReader, int version = int.MaxValue, ...)`（[:338-458](../Shared/Data/ItemData.cs#L338-L458)）用 `if (version > 84/85/107)` 做旧档兼容。

### 2.2 物品网络格式无版本协商

`Shared/ServerPackets.cs` 中 20+ 处 `new UserItem(reader)` 全部走默认 `version = int.MaxValue`，即**线上永远按最新字段解析**。所以：

> 一旦往 `UserItem` 加字段，服务端与 WinForms 客户端必须同版本发布，否则旧客户端读物品会错位。

服务端可用 `Settings.CheckVersion` + `VersionHashes` 在握手阶段拒绝旧客户端（[MirConnection.cs:843-869](../Server/MirNetwork/MirConnection.cs#L843-L869)）。

### 2.3 客户端自己算属性

客户端**不直接使用服务端算好的属性**：`GameScene.cs:5777-5778` 把服务端 `Stats` 存进 `CoreStats`，随后 `UserObject.RefreshStats()`（[UserObject.cs:144-180](../Client/MirObjects/UserObject.cs#L144-L180)）从等级/装备/套装/技能/Buff 重新累加。

> 任何服务端属性来源，都必须在客户端找到对应的累加点，否则会出现「服务端生效、面板不显示」（此前 `Stat.Strong` 就是这种情况）。

### 2.4 数据库版本

`Envir.Version = 118`（[Envir.cs:56-58](../Server/MirEnvir/Envir.cs#L56-L58)）。DB 头部写入版本号（`Envir.cs:2515`），读取时 `LoadVersion > Version` 直接拒载（`Envir.cs:2899-2901`）。

### 2.5 已有可复用的「独立子系统」范本

符文系统是最贴近的先例：定义放 JSON、不进 MirDB、启动时 `RuneRepository.Load()`（[RuneRepository.cs:14-90](../Server/RuneSystem/RuneRepository.cs#L14-L90)），`Envir.LoadDB` 里在 `RuneRepository.Load()` 旁边挂载（`Envir.cs:2910-2911`）。词条系统照此模式即可，**词条定义表不需要动 DB 结构**。

## 4. 数据模型

### 4.1 词条定义 `AffixInfo`

```csharp
public sealed class AffixInfo
{
    public ushort Id;                 // 全局唯一，写进物品
    public string Name;               // 展示名："凶残的" / "之熊"
    public string NameKey;            // 可选：本地化键（Affix_1201），客户端优先查翻译表
    public bool Suffix;               // false = 前缀，true = 后缀
    public int Tier = 1;              // 档位 1..5，同一 Group 可有多档
    public int MinIlvl = 1;           // 该档最低物品等级
    public string Group = "";         // 互斥组：同名组只能出现一次
    public Stat Stat;                 // 作用属性
    public int MinValue = 1;          // 本档数值下限
    public int MaxValue = 1;          // 本档数值上限
    public ItemType[] Slots = Array.Empty<ItemType>(); // 可出现的部位
    public int Weight = 100;          // 抽取权重
    public int[] Excludes = Array.Empty<int>();        // 与这些 Id 互斥（可选）
    public int MaxPerItem = 1;        // 同名组在一件装备上的最大条数
    public string Tags = "";          // 预留：未来共鸣/条件/图鉴分类
}
```

**关键约定**

- `Id` 一旦发布不可复用（存档里存的是 Id）。
- 同一 `Group` 可以有多个 `Tier` 版本，掷骰时先选组、再取 `MinIlvl <= ilvl` 的最高档。
- `MinValue/MaxValue` 属于**该档**，不需要再做插值（暗黑2 也是按档取值），便于平衡。
- `Stat` 只允许 `Stat` 枚举里已定义的值；`AffixRepository.Load()` 里做 `Enum.IsDefined` 校验。
- 数值用 `short` 存储，允许负数（未来可做「诅咒词条」）。
- **一档一条定义**：`Tier` 1..5 各自是独立的 `AffixInfo`，`Group` 相同。ID 规则：前缀 `1000 + 族号×10 + 档位`、后缀 `2000 + 族号×10 + 档位`（例：`1001-1005` 是「凶残的」的 T1–T5，`1011-1015` 是下一族）。每族预留 10 个号，便于将来加 T6 或变体。
- 具体放哪些族、数值多大，见 [词条系统-词条池.md](词条系统-词条池.md)。

### 4.2 物品实例 `AffixInstance`

```csharp
[Serializable]
public struct AffixInstance
{
    public ushort Id;     // 对应 AffixInfo.Id
    public byte Tier;     // 冗余档位，便于展示/未来重铸判断
    public Stat Stat;     // 冗余属性，客户端无需词条表即可算属性
    public short Value;   // 已掷定的数值
    public byte Flags;    // 预留：bit0 锁定，bit1..3 来源（DROP/REFORGE/GM/TRANSFER）
}
```

**为什么冗余 `Stat`/`Value`**：客户端 `RefreshStats` 要能独立算属性；名表包只负责显示名字。这样即使客户端词条表缺失/版本不一致，属性面板仍然正确。

`UserItem` 新增：

```csharp
public List<AffixInstance> Affixes = new List<AffixInstance>();
public ushort AffixIlvl;   // 生成时怪物等级，0 = 无词条；未来洗练按原 ilvl 重掷
```

### 4.3 词条显示词形（不并入装备名）

**决策：词条名不拼接到装备名上。** 装备名在所有界面（地面、聊天、摆摊、仓库、交易、tooltip 标题行）一律只显示 `Info.FriendlyName` 基础名；词条只以两种形式体现：

1. **tooltip 详情**：独立一节，逐行列出前缀/后缀词形 + 属性 + 数值（§8.2）。
2. **名字染色**：按最高词条 Tier 给名字整体上色（§8.1）。

```
tooltip 标题行：炼狱之熊            ← 基础名，颜色 = 最高词条 Tier
tooltip 详情：  凶残的   最大攻击 +8   ← 前缀词形
                之熊     最大攻击 +11  ← 后缀词形
```

**词形约定**

| 位置 | 词形 | 示例 |
|---|---|---|
| 前缀（`AffixInfo.Suffix == false`） | 「形容词 + 的」 | `凶残的`、`锋利的` |
| 后缀（`AffixInfo.Suffix == true`） | 「之 + 名词」 | `之熊`、`之焰` |
| 多条同类 | 全部列出，按 Tier 降序 | 不做「只取最高一条」的合并 |

- 词形由 `AffixInfo.Name` 直接给出完整文本，客户端不做中文拼接（英文走 `NameKey` 翻译，见 §8.5）。
- 因为不进名字，**不需要** `FriendlyName` 改造，也**不影响**摆摊搜索、聊天链接、日志——这些地方看不到词条（后续要做「按词条筛选」再单独加 UI，见 §10）。
- 需要保留的小工具函数：`AffixNaming.HighestTier(item)`（染色用，无词条返回 0）、`AffixNaming.DisplayLines(item)`（tooltip 行文本，客户端可复用于其它界面）。

### 4.4 ilvl 与 Tier 映射

| Tier | MinIlvl | 说明 |
|---|---|---|
| 1 | 1 | 新手图 |
| 2 | 21 | |
| 3 | 41 | |
| 4 | 61 | |

| 物品 `ItemGrade` | 词条数 | 前缀上限 | 后缀上限 |
|---|---|---|---|
| None / Common | 0 | 0 | 0 |
| Rare | 2 | 1 | 1 |
| Legendary | 3 | 2 | 1 |
| Mythical | 4 | 2 | 2 |

## 5. 生成算法

### 5.1 伪代码

```csharp
public static bool TryRoll(UserItem item, int ilvl, ItemGrade grade)
{
    if (!Settings.AffixSystemEnabled) return false;
    if (item?.Info == null || ilvl <= 0) return false;

    var rule = AffixRules.For(grade);          // 词条数 / 前缀配额 / 后缀配额
    if (rule.Count == 0) return false;

    var pool = AffixRepository.For(item.Info.Type);   // 已按部位预索引
    if (pool.Count == 0) return false;

    var picked = new List<AffixInstance>();
    int prefix = 0, suffix = 0;

    for (int i = 0; i < rule.Count; i++)
    {
        bool wantSuffix = suffix < rule.MaxSuffix && (prefix >= rule.MaxPrefix || Envir.Random.Next(2) == 1);
        var candidates = pool.Where(x => x.Suffix == wantSuffix
                                      && x.MinIlvl <= ilvl
                                      && IsAllowed(x, picked)).ToList();
        if (candidates.Count == 0) continue;

        var info = WeightedPick(candidates);             // 按 Weight
        int value = Envir.Random.Next(info.MinValue, info.MaxValue + 1);

        picked.Add(new AffixInstance { Id = info.Id, Tier = (byte)info.Tier, Stat = info.Stat, Value = (short)value });
        if (wantSuffix) suffix++; else prefix++;
    }

    if (picked.Count == 0) return false;
    item.Affixes = picked;
    item.AffixIlvl = (ushort)Math.Min(ilvl, ushort.MaxValue);
    return true;
}

// 互斥：同 Group 只能一条；Excludes 命中则跳过
static bool IsAllowed(AffixInfo info, List<AffixInstance> picked) { ... }
```

### 5.2 掉落点接入

只在以下位置调用（不改 `CreateDropItem` 签名，其余 11 个调用点天然无词条）：

| 位置 | ilvl |
|---|---|

| [Dragon.cs:175](../Server/MirEnvir/Dragon.cs#L175) | `Level + 10` |
| [HarvestMonster.cs:67](../Server/MirObjects/Monsters/HarvestMonster.cs#L67) | `Level` |
| [NPCSegment.cs:4600](../Server/MirObjects/NPC/NPCSegment.cs#L4600) | 可选：按地图/固定 30 |

接入方式：

```csharp
UserItem item = Envir.CreateDropItem(dropItem);
if (item == null) continue;
AffixService.TryRoll(item, Level, item.Info.Grade);   // ← 新增一行
```

### 5.3 与现有随机附加属性的关系

- 两者独立掷骰：`UpgradeItem` 在 `CreateDropItem` 内部已执行完，词条在其后追加。
- 互不引用：词条不写 `AddedStats`，随机附加属性也不看 `Affixes`。
- 允许同时存在：一件装备可以既有「+3 MaxDC（随机附加）」又有「凶残的 +5 MaxDC（词条）」。这就是「独立系统」的直观表现。

### 5.4 生成上限保护

- 词条数硬上限 4，防止未来规则改崩。
- `MaxValue` 上限做一次 `Math.Min(value, 255)` 级保护（`short` 存得下，但战斗数值不该失控）。
- 生成后调用 `AffixService.Validate(item)`：检查 Id 存在、Tier 匹配、数值落在该档范围内（非法则丢弃该条并记日志）。

## 7. 属性生效

### 7.1 服务端

[HumanObject.cs:1913-1929](../Server/MirObjects/HumanObject.cs#L1913-L1929) 是装备属性汇总点：

```csharp
Stats.Add(realItem.Stats);
Stats.Add(temp.AddedStats);

AffixService.Apply(temp, Stats);   // ← 新增：遍历 Affixes，Stats[Stat] += Value

Stats[Stat.MinAC] += temp.Awake.GetAC();
...
```

孔内宝石同理：`RefreshSocketStats`（`HumanObject.cs:1946` 调用，实现 :2006-2034）内对 `temp.Slots[i]` 也要 `Apply` 一次，保证「带词条的宝石插进孔里」也能生效。

### 7.2 客户端

`UserObject.RefreshStats()`（[UserObject.cs:144-180](../Client/MirObjects/UserObject.cs#L144-L180)）加一个与 `RefreshEquipmentStats()` 并列的方法：

```csharp
private void RefreshAffixStats()
{
    foreach (var item in Equipment) ApplyItem(item);
    foreach (var item in Equipment) foreach (var s in item?.Slots ?? Array.Empty<UserItem>()) ApplyItem(s);
}
```

> 必须与服务器同一套规则。**这是本项目最容易漏的一步**——漏了就是"服务端 +5 攻击、面板不显示"。

### 7.3 计算顺序

`RefreshStats` 的顺序是：基础 → 装备/词条 → 套装 → 技能 → Buff → 百分比放大（`Stat.HPRatePercent` 等）→ `RefreshStatCaps()`。

词条位置与 `AddedStats` 相同（平加，在百分比放大之前），所以：

- 百分比类词条（本期不做）如果将来要加，必须放在放大**之前**并标注为「基础值加成」。
- 词条数值最终受 `RefreshStatCaps()` 截断（Caps 来自 `Configs/BaseStats{职业}.ini` 的 `[Caps]`，`Settings.cs:916-949`）。**调词条数值时要一起看 Caps**，否则 `MaxDC` 类词条很容易撞顶。

## 8. 展示（WinForms 客户端）

> 范围：只改 `Client`（WinForms 客户端）。

### 8.1 名称染色

现状：`NameInfoLabel`（[GameScene.cs:6884-6926](../Client/MirScenes/GameScene.cs#L6884-L6926)）用**单个** `MirLabel`，`ForeColour = GradeNameColor(Info.Grade)`，品质文字用 `\n` 拼在同一字符串里 —— 两行只能同色。`MirLabel` 一个实例只有一个 `ForeColour`，所以要做两件事：

**改造点 A：拆成两个 label**（名称行、品质行各一行各一色）：

```csharp
MirLabel nameLabel = new MirLabel
{
    AutoSize = true,
    ForeColour = ItemNameColor(HoverItem),
    Location = new Point(4, 4),
    OutLine = true,
    Parent = ItemLabel,
    Text = HoverItem.Info.FriendlyName
};
// 品质行单独追加在 nameLabel.DisplayRectangle.Bottom，颜色仍用 GradeNameColor(HoverItem.Info.Grade)
```

**改造点 B：新增 `ItemNameColor(UserItem)`**（放在 `GradeNameColor` 旁边，[GameScene.cs:6840](../Client/MirScenes/GameScene.cs#L6840)）：

| 最高词条 Tier | 名字颜色 | 说明 |
|---|---|---|
| 0（无词条） | `GradeNameColor(Info.Grade)` | 保持现状 |
| 1 | `Color.DeepSkyBlue` | 蓝 |
| 2 | `Color.Yellow` | 黄 |
| 3 | `Color.DarkOrange` | 橙 |
| 4 | `Color.Plum` | 紫 |
| 5 | `Color.Red` | 红 |

```csharp
public Color ItemNameColor(UserItem item)
{
    if (item == null) return Color.Yellow;

    switch (AffixNaming.HighestTier(item))   // 无词条返回 0
    {
        case 1: return Color.DeepSkyBlue;
        case 2: return Color.Yellow;
        case 3: return Color.DarkOrange;
        case 4: return Color.Plum;
        case 5: return Color.Red;
        default: return GradeNameColor(item.Info.Grade);
    }
}
```

规则说明：

- 词条色与品质色共用同一套稀有度阶梯，避免两套色板互相打架；颜色的语义统一成「这件东西最稀有的那一层」。
- 品质行仍按 `Info.Grade` 上色，所以「名字红 + 品质黄」（白装出了 T5 词条）是合法组合。
- `(*)` 精炼标记、`hideDura`、Inspect 分支不动。
- 暂不做**分段染色**（前缀染词条色、基础名染品质色）：需要 3 个 label 横向拼接，字号/换行变化时会错位，收益低。

### 8.2 词条区

`CreateItemLabel`（[GameScene.cs:9860-9925](../Client/MirScenes/GameScene.cs#L9860-L9925)）现在固定 11 节，数组扩到 12，插在觉醒之前（名称/攻防/重量之后）：

```csharp
MirControl[] outlines = new MirControl[12];
outlines[0] = NameInfoLabel(item, inspect, hideDura);
outlines[1] = AttackInfoLabel(item, inspect, hideAdded);
outlines[2] = DefenceInfoLabel(item, inspect, hideAdded);
outlines[3] = WeightInfoLabel(item, inspect);
outlines[4] = AffixInfoLabel(item, inspect);      // ← 新增
outlines[5] = AwakeInfoLabel(item, inspect);
...
outlines[11] = GMMadeLabel(item);
```

`AffixInfoLabel` 照 `AwakeInfoLabel`（[:8560-8632](../Client/MirScenes/GameScene.cs#L8560-L8632)）的范式：**一条词条一个 `MirLabel`**，逐行追加在 `ItemLabel.DisplayRectangle.Bottom`，每行单独 `ForeColour`（该条 Tier 色），并同步扩展 `ItemLabel.Size`；`count > 0` 时上下各留 4px 并画分隔块（[:8634-8649](../Client/MirScenes/GameScene.cs#L8634-L8649) 的 outLine）。

行文本（词条名对齐 + 属性名 + 数值）：

```
凶残的   最大攻击 +5
之熊     最大攻击 +8
```

- 词条名按固定宽度补空格对齐，避免中文词条长度差异导致参差。
- 数值格式 `{属性名} +{Value}`；属性名复用现有 `ClientTextKeys.Stat_*`。
- 词条名来自 `GameScene.AffixInfoList`（`S.AffixInfo` 缓存，见 §6.3）；缺失时降级为 `#Id` + 数值，不抛异常。

### 8.3 边界与降级

| 场景 | 行为 |
|---|---|
| `Affixes == null` 或 `Count == 0` | 整节返回 `null`，布局与现在完全一致 |
| 未鉴定（`Identified == false`） | 只显示名称，不显示词条行 |
| 词条表未下发 / 版本不一致 | 行文本降级为 `#Id +值`，名字颜色仍按 Tier |
| Inspect 查看他人装备 | 同 `AttackInfoLabel` 走 `InspectDialog.Level / Class` |
| 词条 Id 不在表里 | 跳过该行并写一次 `DebugText`，不崩 |

### 8.4 其它界面

- 地面物品名、摆摊、聊天、仓库、交易一律只显示 `Info.FriendlyName` 基础名，**不带词条**（见 §4.3）。
- 这些界面**不染色**：本期只改 tooltip 的名称行与词条区。若后续要统一，抽出 `ItemNameColor` 复用即可。

### 8.5 本地化

- 词条名默认取 `AffixInfo.Name`（服务端 JSON 里的中文/英文）。
- 若 `NameKey` 非空且 `ClientTextMap` 有对应键，优先翻译（复用 `ClientTextKeys` 机制与 `Client/Localization/Chinese.json`）。
- 属性名复用现有 `Stat_*` 键，不新增文案。
- 新增的 tooltip 分隔/标签文本（如「词条」前缀）不加，保持与现有觉醒/镶嵌区一致的「无标题直接列行」风格。
